## 1. 页面概述

| 项目 | 内容 |
|------|------|
| 页面名称 | 补货建议（与补货点计算合并） |
| 访问角色 | 库管人员、系统管理员 |

## 3. 功能流程

### 3.1 补货点列表流程

1. 用户进入补货点计算页面
2. 系统调用 `/algorithms/reorder-points` 获取所有物资的补货点数据
3. 系统加载物资列表
4. 用户可按物资名称、编码、库存状态、是否需要补货进行筛选

### 3.2 补货点计算流程

1. 用户点击"开始计算"按钮
2. 系统重新调用 `/algorithms/reorder-points` 获取最新数据
3. 列表数据更新
4. 图表（如显示）同步更新

### 3.3 图表展示流程

1. 用户可选择显示或隐藏图表
2. 图表展示各物资的当前库存、安全库存、补货点对比

## 6. 数据字段说明

### 6.1 补货点计算公式

```
安全库存 = 日均消耗量 × 采购提前期 × 安全系数
补货点 = (日均消耗量 × 采购提前期) + 安全库存
日均消耗量 = 近5年消耗总量 / 天数
安全系数默认值 = 1.5
```

### 6.2 补货点接口返回字段

| 字段 | 类型 | 说明 |
|------|------|------|
| materialId | Long | 物资ID |
| materialName | String | 物资名称 |
| materialCode | String | 物资编码 |
| currentStock | Integer | 当前库存 |
| safetyStock | Integer | 安全库存 |
| reorderPoint | Integer | 补货点 |
| dailyConsumption | BigDecimal | 日均消耗量 |
| leadTime | Integer | 采购提前期 |
| safetyFactor | BigDecimal | 安全系数 |
| stockStatus | String | 库存状态：LOW/NORMAL/HIGH |
| needReorder | Boolean | 是否需要补货 |

### 6.3 物资表（material）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 主键 |
| code | String | 物资编码 |
| name | String | 物资名称 |
| category | String | 物资类别 |
| currentStock | Integer | 当前库存 |
| minStock | Integer | 安全库存（最低库存） |
| leadTime | Integer | 采购提前期（天） |
| safetyFactor | BigDecimal | 安全系数 |
| unitPrice | BigDecimal | 单价 |

## 10. 与原PRD差异说明

**原PRD规划内容（待实现）：**
- 独立的补货建议页面
- Tab切换：紧急补货 / 全部建议 / 已处理
- 确认补货按钮（标记为已处理）
- 紧急度说明

**当前实现版本：**
- 补货建议功能合并到补货点计算页面
- 通过库存状态下拉框筛选"库存过低"物资
- 通过"是否需要补货"下拉框筛选需要补货的物资
- 暂无"确认补货"功能

**后续迭代方向：**
- 可根据业务需求添加确认补货功能
- 可添加已处理记录的历史查看功能
