## 3. 功能流程

### 3.1 补货点列表流程

1. 用户进入补货点计算页面
2. 系统自动调用接口获取补货点数据
3. 系统加载图表
4. 系统加载物资列表

### 3.2 筛选流程

1. 用户输入物资名称筛选
2. 用户输入物资编码筛选
3. 用户选择库存状态筛选（库存过低/正常/库存过高）
4. 用户选择是否需要补货筛选
5. 点击"筛选"按钮应用条件
6. 点击"重置"按钮清空条件

### 3.3 重新计算流程

1. 用户点击"开始计算"按钮
2. 系统调用接口重新计算补货点
3. 系统显示计算完成提示
4. 系统更新图表和数据列表

## 6. 数据字段说明

### 6.1 补货点计算公式

```
安全库存 = 日均消耗量 × 采购提前期 × 安全系数
补货点 = (日均消耗量 × 采购提前期) + 安全库存
日均消耗量 = 近5年消耗总量 / 天数
```

### 6.2 返回数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| materialName | String | 物资名称 |
| materialCode | String | 物资编码 |
| currentStock | Integer | 当前库存 |
| safetyStock | Integer | 安全库存 |
| reorderPoint | Integer | 补货点 |
| dailyConsumption | BigDecimal | 日均消耗量 |
| leadTime | Integer | 采购提前期（天） |
| safetyFactor | BigDecimal | 安全系数 |
| stockStatus | String | 库存状态：LOW/NORMAL/HIGH |
| needReorder | Boolean | 是否需要补货 |

## 7. API接口

### 7.1 获取补货点列表

```
GET /api/algorithms/reorder-points
响应: Result<List<ReorderPointVO>>
```

### 7.2 批量计算

```
POST /api/algorithms/schedule/reorder-point-calculation
响应: Result<Void>
```

说明：批量计算任务由系统后台执行，前端通过刷新获取最新计算结果。
